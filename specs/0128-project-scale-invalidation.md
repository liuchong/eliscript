## Summary

Eliscript owns a deterministic 1,000-module project acceptance graph for clean
builds, no-op reuse, chain-leaf invalidation, and shared-dependency
invalidation. The suite invokes the public self-hosted `eliscript-build`
command, validates every reported dependency edge, evaluates changed behavior,
and requires incremental artifacts and graph identities to equal forced clean
builds.

This specification completes M12-02 and AC-09. It supplies the project-scale
half of AC-19; specification 0129 independently supplies the worker soak and
completes the combined criterion.

## Fixed Graph

Version 1 generates files `m0000.eli` through `m0999.eli` with the following
connected topology:

| Region | Modules | Edges |
| --- | ---: | ---: |
| Root | 1 | 360 outgoing |
| Chain | 399 | 398 internal |
| 50 four-module diamonds | 200 | 200 internal |
| 10 ten-module cycles | 100 | 100 internal |
| Shared dependency plus fan-out | 300 | 299 importer edges |
| **Total** | **1,000** | **1,357** |

The root reaches the chain head, every diamond top, one member of every cycle,
and all 299 shared-dependency importers. Cycle edges use side-effect imports so
the graph exercises cycle planning without temporal-dead-zone behavior. Other
edges import one unique numeric export and make dependency changes observable.

The version 1 topology SHA-256 is
`1a0edcb5c8ef1d11694db02db48d1f0b04c6a56733e8defa4ceb5109813e89f4`.
The initial, leaf-mutated, and shared-mutated source-tree identities are also
fixed by the executable test. Timing, process identity, temporary paths, and
generated compiler output are excluded from source and topology identities.

## Invalidation Semantics

For standard ESM builds, a dependency content change does not require an
importer artifact to be regenerated. The importer already names a stable
output path, so loading the changed dependency gives it the new behavior. The
semantically affected runtime closure and the set of sources requiring
compilation are therefore deliberately different:

- changing chain leaf `m0399.eli` changes the evaluated chain-head value but
  recompiles only `m0399.eli`
- changing shared dependency `m0700.eli` changes values exported by all 299
  importers but recompiles only `m0700.eli`
- unrelated graph regions retain both their behavior and generated bytes

This is the stable policy from specification 0031, not a weakened substitute
for reverse-dependency invalidation. Exact dependency records, runtime values,
and forced-clean equivalence prove that reused importers are valid.

## Acceptance Sequence

The suite performs these phases in one owned temporary tree:

1. an empty-output cached build compiles all 1,000 modules
2. a no-op build reuses all 1,000 modules with `verified` decisions and changes
   no artifact byte
3. a chain-leaf edit compiles exactly one module and reuses 999
4. a forced clean build compiles all modules and matches the leaf-incremental
   graph digest, 2,001-file artifact tree, and evaluated values
5. a shared-dependency edit compiles exactly one module and reuses 999
6. a second forced clean build matches the shared-incremental graph digest,
   artifact tree, and evaluated values

Every phase validates the complete 1,000-module dependency report against the
fixed topology. Digest comparison covers every generated `.mjs`, Source Map,
and `eliscript-project.json` byte rather than a selected fixture subset.

## Resource Contract

The version 1 hard limits are:

| Resource | Limit |
| --- | ---: |
| One build command | 120,000 ms |
| Captured stdout or stderr | 16 MiB |
| Source tree | 8 MiB |
| One artifact tree | 64 MiB |
| Complete temporary tree | 136 MiB |
| One build process maximum RSS | 512 MiB |

The report records compiler phase timing, external wall duration, and maximum
resident memory for every build. One acceptance run on the declared local host
completed individual builds in 95-299 ms with a highest observed maximum RSS
of 83,214,336 bytes; those observations demonstrate headroom but are not
portable artifact identities.

Source writes are batched, artifact hashing reads one file at a time, captured
streams are bounded, and each child has a deadline. Normal completion,
exceptions, and termination signals stop owned children and remove the owned
temporary directory. The suite starts no server and leaves no persistent
process.

The public command is:

```sh
bun run scale:project
```

## Acceptance Criteria

- **PSI-01:** The fixed graph contains exactly 1,000 reachable modules and
  1,357 exact dependency edges with chain, diamond, cycle, and wide fan-out
  regions.
- **PSI-02:** The topology and all three generated source-tree identities match
  their version 1 SHA-256 baselines.
- **PSI-03:** The initial build compiles 1,000 modules and a no-op rebuild reuses
  1,000 modules with verified cache decisions.
- **PSI-04:** The no-op rebuild changes no generated artifact byte.
- **PSI-05:** A chain-leaf edit compiles exactly `m0399.eli`, reuses 999 modules,
  and changes the evaluated chain-head result by the declared amount.
- **PSI-06:** A shared-dependency edit compiles exactly `m0700.eli`, reuses 999
  modules, and changes values through the first and last of 299 importers.
- **PSI-07:** Unrelated evaluated chain and fan-out values remain unchanged for
  each mutation.
- **PSI-08:** Both incremental states equal forced clean builds in complete
  artifact-tree bytes, public graph digest, and evaluated behavior.
- **PSI-09:** Every build duration, maximum RSS, source tree, artifact tree,
  captured stream, temporary tree, child lifetime, and cleanup path remains
  inside the documented limit.
- **PSI-10:** The default test suite executes the fixed acceptance graph without
  an application framework, bundler, publisher, site generator, hosting
  system, or development server.
