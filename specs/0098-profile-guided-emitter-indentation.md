## Summary

The self-hosted emitter now indents generated fragments by scanning complete
line segments. Each non-empty line contributes one indentation fragment and
one original-source slice; the final text is assembled with one native join.
Source Map marks are translated by a monotonic mark cursor and an explicit
output-length counter.

The previous character-by-character implementation remains executable as
`reference-indent`. It repeatedly extends the output string and is not used by
normal compilation. Production is accepted only because both algorithms
produce byte-identical text and exactly equal ordered mark arrays over the
maintained compiler corpus and explicit line-boundary cases.

## Profile Evidence

A repeated whole-compiler profile covered six complete compilations of all
eleven maintained self-hosted modules with Source Maps. Before this slice, the
character indentation loop and its generated closures accounted for about
15.1% total sampled time and several of the largest self-time entries.

The same workload after this slice no longer places the old character loop
among the dominant paths. The production line/mark loop accounts for about
1.6% total sampled time in that follow-up sample. Sampling identifies and
confirms the hotspot movement; the reproducible benchmark owns the performance
decision.

## Text Semantics

Indentation preserves these exact rules:

1. A non-empty line receives two ASCII spaces before its first code unit.
2. A line containing only LF receives no spaces.
3. CR is ordinary content; CRLF therefore receives indentation before CR.
4. A trailing LF is preserved and does not create an additional indented line.
5. Empty input remains empty.
6. ECMAScript strings remain indexed in UTF-16 code units.

The production algorithm locates the next LF with native `indexOf`, appends a
source `slice` ending at that LF or end of input, and advances monotonically.
It does not split or reconstruct Unicode code points.

## Source Map Mark Semantics

Marks are ordered by source offset. For every mark whose offset belongs to the
current line segment, production computes:

```text
output offset = current output length + mark offset - segment start
```

`current output length` already includes the two spaces for a non-empty line,
so a mark on its first character moves after indentation. Marks on an empty
line's LF do not move. Duplicate marks retain order and equal output offsets.
A mark at `source.length` remains ignored, preserving the existing contract.

The algorithm is linear in source length, line count, and mark count. It does
not rescan prior text or derive mark offsets from the accumulated string.

## Reference Contract

`reference-indent` is the original character loop. It checks every UTF-16 code
unit, appends indentation at line starts, copies marks at each exact source
offset, and extends the result string one character at a time.

The reference must remain independent and readable. It must not delegate to
the production line scanner, share its text-part array, or compute offsets with
the production output-length state. Normal emitter paths call only `indent`.

## Reproducible Benchmark Contract

`tools/compiler/indent-benchmark.mjs` compiles all maintained self-hosted
modules to real IR and real generated JavaScript. It partitions generated
modules into 22 declaration fragments containing 306,925 bytes and 20,622
real emitter Source Map marks, then adds ten explicit boundary fragments.

Before timing, all 32 optimized/reference results must have byte-identical text
and structurally equal ordered marks. The reviewed macOS arm64 report records:

- 247,668 bytes of maintained compiler source
- 11 compiler programs and 22 generated declaration fragments
- 307,621 generated bytes and 20,638 marks
- 10 empty, blank-line, duplicate-mark, trailing-mark, CRLF, and Unicode cases
- 9 alternating samples after warmup, with 20 corpus passes per sample

The reviewed median is 10.230917 ms for line-segment indentation and
151.913875 ms for the retained character reference, a 14.848510x local
speedup. The decision threshold was fixed at 10x before recording the report.
This local result supports the implementation choice; it is not a universal
host-performance promise.

Every compiler source and the benchmark implementation participates in the
SHA-256 digest. Default tests recompute that digest and validate the report,
but do not make wall-clock timing a normal CI gate.

## Core Boundary

This implementation belongs to the self-hosted compiler and Source Map model.
Application frameworks, React integrations, Vite adapters, bundlers, blog or
site generators, publishing tools, and development servers do not participate
in its dependencies, corpus, performance decision, or acceptance evidence.

## P4 Status

This is the third profile-guided compiler slice with an executable semantic
reference and source-bound report. It removes indentation from the dominant
profile entries, but does not close P4. Remaining compiler and standard-library
hot paths require their own profile evidence, independent reference, and
measured gain.

## Acceptance Criteria

- **ESI-01:** Production indentation advances by complete LF-delimited source
  segments and assembles text with a single final join.
- **ESI-02:** Non-empty, empty, trailing-LF, CRLF, and UTF-16 text behavior is
  byte-identical to the previous implementation.
- **ESI-03:** Ordered and duplicate marks retain spans and exact translated
  offsets; source-end marks retain the previous ignored behavior.
- **ESI-04:** The original character/string implementation remains executable
  as an independent reference and is absent from normal compilation.
- **ESI-05:** Production and reference results agree over every maintained
  self-hosted compiler fragment and all explicit boundaries.
- **ESI-06:** The reviewed report contains source and host fingerprints, raw
  samples, medians, corpus counts, checksum, threshold, and passing decision.
- **ESI-07:** The reviewed local median speedup is at least 10x over the
  retained reference.
- **ESI-08:** Default tests reject digest drift, malformed or incomplete
  reports, failed equivalence, and failed threshold decisions.
- **ESI-09:** Seed/self-hosted ESM and Source Map parity plus the
  three-generation fixed point remain unchanged.
- **ESI-10:** No application framework, UI library, Vite dependency, bundler,
  site generator, publishing tool, or development server participates in the
  core implementation or evidence.
