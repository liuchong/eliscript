From one Lisp form to a running module.

Requirements & install

Install the published 0.1.3 compiler and runtime from npm on Node.js 24+ (>=24.0.0, CI pinned at 24.20.0) or Bun 1.4+ (>=1.4.0)—no Emacs installation is required to run the packaged compiler:

npm install eliscript@0.1.3
# or: bun add eliscript@0.1.3
npx eliscript --help

Building from a source checkout or running the Emacs editor integration uses GNU Emacs 29+ (CI verifies against GNU Emacs 32.0.50), Bun 1.4+, and Node.js 24+:

emacs --version
bun --version
node --version

Install the locked JavaScript dependencies used by optional browser checks (react 19.3.1, vite 8.3.5, playwright-core 1.64.1):

bun install --frozen-lockfile

The Emacs Lisp seed compiler itself has zero JavaScript dependencies; a clean Emacs installation can bootstrap Stage 0 from source.

Run or compile a file

Create hello.eli:

(module hello
  (defun greet (name)
    (str "Hello, " name "!"))

  (print (greet "ECMAScript"))
  (export greet))

Execute .el or .eli files directly through the unified CLI, or compile ahead of time to standard ECMAScript:

./bin/eliscript hello.eli
./bin/eliscript --output dist/hello.mjs hello.eli

Without --output, generated ECMAScript is written to standard output.

For debugger-ready output, generate an external Source Map v3 file:

./bin/eliscript --source-map --output dist/hello.mjs hello.eli

This writes dist/hello.mjs.map and links it from the generated module.

Run the module

bun run dist/hello.mjs

The generated file is standard ESM. Bun is the reference host, but the compiler does not emit proprietary Bun syntax.

Build a source graph

bun run build:stdlib-cli
bun run dist/project/examples/stdlib-cli/main.mjs

The project builder discovers relative .eli imports after macro expansion, keeps every source below the selected root, mirrors the directory tree as .mjs, and emits a source map beside each module. A deterministic eliscript-project.json records the complete graph, SHA-256 identities, and incremental cache metadata. Repeat builds reuse unchanged modules; pass --no-cache to force compilation.

Tooling can request a report with stable cache and per-module decisions plus phase timings:

./bin/eliscript-build --json --root . --out-dir dist/project \
  examples/stdlib-cli/main.eli

Timings are observational and never enter the deterministic manifest or cache identity. Without --json, successful builds print only the generated entry path.

Compile live in the browser

Any web page can compile and hot-reload Eliscript directly in the browser without a server or repository checkout. Load the standalone browser loader and declare either a data-eliscript entry or inline/external <script type="text/eliscript"> tags:

<script defer src="https://unpkg.com/eliscript@0.1.3/dist/browser/loader.js"></script>

<script type="text/eliscript">
(module web.hello
  (print "Compiled live in the browser!"))
</script>

For programmatic in-memory compilation, optimization ({ optimize: true, minify: true, closureCompiler }), extensionless package imports (such as (import "eliscript/runtime/core/order" sort)), and multi-module execution, import eliscript/browser directly:

import { compileSource, compileProject, moduleGraphUrls, runSource, mountEliscriptScripts } from "eliscript/browser";

const { module } = await runSource(
  "(module demo (defun double (x) (* x 2)) (export double))",
  "demo.eli"
);
console.log(module.double(21)); // 42

Use persistent values & Emacs-compatible extensions

(module collections
  (import "eliscript/runtime/core/collection" assoc get)

  (defconst original {:name "Eliscript" :tags #{:lisp :esm}})
  (defconst updated (assoc original :status :stable))

  (print (get original :status :missing))
  (print (get updated :status)))

Vector, Map, Set, List, Queue, Record, and sorted collection values are immutable. Updates return a new root while sharing unchanged internal structure. Generic collection operations dispatch through open protocols with reference-identity equality short-circuiting and compact O(1)-step Zipper navigation, while Transient builders provide an isolated construction path for batch updates.

In GNU Emacs or JavaScript, load the unified Emacs runtime ((require 'eliscript-runtime) in Emacs or import "eliscript/runtime/lisp" in JS) to combine standard Emacs Lisp semantics with defun-case, let-bind / defun-bind, cl-defstruct-persistent, defmodule, with-async-scope, and lossless js-false / js-null / js-undefined sentinels.

Run optional applications

Application examples consume public ESM and host boundaries. They are useful interoperability probes, but no framework or bundler is part of the language compiler, runtime, standard library, or core maturity result.

React counter

bun run compile:react-counter
bun run react-counter

The first command emits a source-mapped ESM module through react/jsx-runtime. The second renders it with react-dom/server, proving the generated element tree without a bundler.

Start the interactive browser application or create its production bundle:

bun run dev:react-counter
bun run build:react-counter

The Vite adapter compiles .eli modules, composes source maps, handles CSS and image assets, and enables React Fast Refresh.

Org publishing

Export the example articles through Emacs as a deterministic ESM data module:

bun run org:export

Run the fully custom React publishing site or create its static production bundle:

bun run dev:org-site
bun run build:org-site

The application itself is written in Eliscript. Its adapter exposes the Org directory as a virtual module and reloads article changes during development.

Build the bootstrap modules

make bootstrap-release
make verify-bootstrap

make bootstrap-release cleans generated outputs, builds the Emacs Lisp Stage 0 seed, and drives the Stage 0 → Stage 1 → Stage 2 → Stage 3 self-hosted closure. make verify-bootstrap independently checks that Stage 2 and Stage 3 match byte-for-byte. Compile through the portable driver with:

./bin/eliscript-portable --output dist/program.mjs source/program.eli

Every compiler module, runtime module, and Source Map in Stage 2 and Stage 3 matches identically.

Emacs portable acceleration

(defportable score-values (values)
  (length values))

./bin/eliscript --portable score-values --output dist/score.mjs source.eli

defportable validates the complete immutable dependency closure. The generated manifest lets Emacs invoke score-values directly by Eliscript name.

bun run benchmark:worker

The benchmark compiles one pure workload, starts a long-lived worker, verifies equal Emacs and Eliscript results, and reports compilation and execution timings cleanly.

(require 'eliscript-index)

(let ((session (eliscript-index-start)))
  (unwind-protect
      (eliscript-index-search-sync
       session '(("intro" . "Emacs and JavaScript")) "javascript")
    (eliscript-index-stop session)))

The indexing example compiles a source-mapped portable project closure, follows its data and object dependencies, tokenizes editor-owned text, scores documents concurrently, and maps any errors cleanly back to Eliscript source locations.

Run the test suite

bun run test

This runs the Emacs test suite, compiler and runtime tests, public CLI fixtures, deterministic snapshots, source-map validation, Bun/Node execution, and separately partitioned application checks.

The portable standard library and protocol-driven persistent collection core run through the same Eliscript module pipeline. Application adapters are tested separately and contribute no core maturity credit.
